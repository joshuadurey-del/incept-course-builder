September 17 to 20: what the HumGeo remediation record teaches the next course build

Source: the HumGeo remediation record (FINDINGS) on the course repository's main branch at commit ffcc7b61, read against this page, the retro entries and spec rules R8 and R9 on 2026-09-22. Of 60 rule-shaped statements in the record, 15 were already here in full. This entry carries the rest: 20 new rules and 25 amendments to rules already here in a general or partial form. Each names the Course Builder step it binds to and links the FINDINGS heading that holds the measured numbers.

New rules

  • Cite private evidence by identity and hash; secure rubrics, answer keys, credentials and signed report URLs never enter the course record. The HumGeo record names each native receipt by SHA256 and keeps the originals in the private root. Builder step: course record (FINDINGS) and evidence store. Receipt: Baseline and reporting identity (H2).
  • Report unique-item counts and occurrence counts separately; raw finding counts overlap within items and are never summed as repair counts. HumGeo: 311 ordering, 767 question quality and 26 Faultless Bar findings sat on 598 items; run 2 counted 3,069 occurrences on 2,978 unique items. Builder step: p6 QC loop (count reporting). Receipt: Baseline and reporting identity (H3).
  • An instrument defect is ruled per finding class with item and check fingerprints, source evidence and a reviewer; it is never a blanket exemption. HumGeo ruled 238 practice-without-instruction rows and 73 late-foundation rows by class with a row-by-row census, and left 4 prerequisite-drift rows as real. Builder step: p6 QC loop (ruling record). Receipt: First queue (H5).
  • Every failed item gets one of four decisions (repair, drop candidate, retain-with-ruling, defer); a ruling clears zero QC points, a defer keeps the defect, and any changed input reopens the ruling. The row records item id, finding ids, input fingerprint, EK/LO, placements, evidence, decision, reviewer and date, floor impact, the live action and the later hosted result. Builder step: p6 QC loop (item decision ledger). Receipt: Item decisions (H8).
  • Read the floor per pool from the course's own blueprint and manifests, never from another course; land a floor verifier that censuses every lesson and gate form, counts a moved-and-dropped item once and goes red on a forced known-bad before the first drop. HumGeo's floors: at least one sync item per lesson, 15 per gate form with the thinnest form at 12 or more, fixed cumulative and final forms. Builder step: p3 bank gates / p6 drop gate (floor verifier). Receipt: Drop floor and coverage ledger (H11).
  • A render check row whose page never mounted its root is not content evidence; uncaptured FRQs stay unmeasured; a render run never stands in for grading, result isolation or XP checks. Builder step: p7 walk and accept (render evidence scope). Receipt: Hosted rounds and presentation evidence (H16).
  • Bind test identity, the permitted capture and submission behavior and the secure-content boundary before launching a render capture, because the capture workflow can submit answers. Builder step: p7 render checks (launch preconditions). Receipt: Hosted rounds and presentation evidence (H17).
  • Compare QC numbers only under the same check scope; another course's percentage with checks disabled is not this course's acceptance, and missing reviews, unresolved findings and local rulings are reported as separate facts. Psych run 5 disabled the Faultless Bar and learning-science checks; HumGeo ran both on. Builder step: p6 bar statement. Receipt: Factory precedent and acceptance boundary (H18).
  • Filter a rewrite worklist by question type and pre-screen the live shape before any drafting spend; an MCQ redraft can never replace an extended-text item. Campaign 3 wasted 88 drafts; operator 2 excluded 39 wrong-shape rewrites. Builder step: draft-judge loop (worklist filter). Receipt: Campaign 3 and Operator 2 population (H22).
  • Review every not-taught finding against the topic's teaching text with one quoted evidence sentence before redrafting; a taught item is a false reject and stays as served. HumGeo: 59 of 122 were taught and kept; 63 went to the rewrite lane. Builder step: draft-judge loop (review before rewrite). Receipt: Lane C taught / not-taught review (H25).
  • A render run where no row mounted its root is an instrument null; freeze it and run render checks after the replacements land, never before. Run ac714df3: 0 of 438 rows had a render root. Builder step: p7 render checks (ordering). Receipt: Presentation QC run ac714df3 (H26).
  • Record a deferred defect class once with its census, its route and the expectation that it keeps failing every run; change embedded checks by editing the authored source, rebuilding assets and republishing to the new key. 82 video checks, 1.3 percent of judged items, deferred for the release. Builder step: p6 QC loop (known-ruled classes). Receipt: Video checks and Ruling: the 82 video checks are deferred (H28).
  • Pilot each drafting model on a handful of items and pick by its measured structural pass rate before spending on the full run. HumGeo measured 96 percent against 69 percent on the same worklist. Builder step: draft-judge loop (drafter choice). Receipt: Factory judge over the rewrites (H33).
  • Treat the factory item judge as the gate and the hosted run as the acceptance; a judge pass can still fail the hosted reader, and the run's cache-miss count shows which items it judged fresh. One of 280 fresh replacements failed answer_in_stem after passing the item judge. Builder step: p6 QC loop (acceptance versus gate). Receipt: Hosted Course QC run 1 (H37).
  • Report the Faultless Bar's sign-off gates apart from its automated checks; a red sign-off gate is a pending signature, not a content failure. Builder step: p6 bar statement; p8 sign-off. Receipt: Hosted Course QC runs 1 and 2 (Faultless Bar lines) (H38).
  • Wire one visible mastery-gate form per topic; the blueprint's extra forms are alternates for rotation, not extra gates. HumGeo students saw three gates per topic until 136 form rows were tombstoned. Builder step: p5 tree (gate wiring). Receipt: Topic structure had five separate causes (H41).
  • Every renumbering pass checks for sort-order collisions with the passes before it; sub-lessons run instruction, practice, gate with no duplicate positions. Three separate passes left duplicate positions in many topics. Builder step: p5 tree (renumber check). Receipt: Topic structure had five separate causes (H42).
  • Rule ordering findings by class (assessment-only lessons, title heuristics, real prerequisite drift), state the residue the ruling predicts, and confirm it on the next run. HumGeo predicted 18 unit-level rows would remain; run 2 reported exactly those 18. Builder step: p6 QC loop (ordering class rulings). Receipt: Ordering check rulings and Lane C1 (H45).
  • Shard redraft loop inputs so no command line carries the whole worklist; a hung loop is stopped and its items recorded as fails, not waited on. One HumGeo loop hung 56 minutes on an oversized xargs line. Builder step: draft-judge loop (input sharding). Receipt: Campaign 6 and run 6 (H52).
  • Where the render instrument cannot reach a resource kind, accept it as presentation-unverified by the instrument and record the owner's walk as an enrolled student once as the evidence. Builder step: p7 walk and accept (presentation evidence). Receipt: 2026-09-19 AFK run (H53).

August 4 to September 21: what the APWH build teaches the next course build

Source: the APWH build (retrospective) and its 57-lesson table on the course repository's main branch. This entry carries only the rules the pages did not yet state: 25 new rules, 27 amendments to rules already here in a HumGeo-only or partial form, and 2 period lessons outside the table. Each names the Course Builder step it binds to and links its receipt; the table row and the period section hold the measured numbers.

New rules

  • Fix the content bar (mock shape, stimulus share, practice cap) in the course profile before the bank is generated. On APWH the mock ruling arrived on day 38 and retired 2,172 items. Builder step: content step (p3 bank gates). Receipt: L3, period 5.
  • The acceptance instrument (the Faultless Bar) must run from a pushed ref before any content work depends on its verdicts; the step 1 oracle gate fails closed when it does not. Builder step: step 1 oracle gate / p5 cold QC. Receipt: L5, period 2.
  • Read the hosted QC reader's code (checks.py, timeback_reader.py) and run one small hosted job before any structural write; ship the hidden article-text block, static check XML and the stimulus in every judge payload from the first publish. Builder step: p6 cold QC (pre-write reader check). Receipt: L8, period 7.
  • Once a namespace publish exists, cold QC judges the native course id, never the source course id. Builder step: p6 cold QC (release .53). Receipt: L9, period 7.
  • The hosted verdict cache is part of the instrument: its key is prompt version, course, question and lesson context, with no cold flag; above about 2,000 items the job record reads FAILED and no email is sent, so the loop polls on report presence. Builder step: p6 QC loop. Receipt: L10, period 7.
  • Read the stored fatal codes before any paid re-judge; never call the judge poster with an empty slot file, because it judges the whole pool. Builder step: draft-judge loop. Receipt: L14, period 7.
  • Name the course's own defect classes from its own bytes before reusing another course's scanner; a fixed-string class gets a free scanner before any model critic; a zero from a filter needs a positive control. Builder step: census step before any campaign. Receipt: L15, period 5.
  • Budget a source fold and re-pin beside every live item wave; a live rewrite breaks the publication envelope, so each wave needs a source landing plus a republish (about 2,300 writes, about 65 minutes on APWH). Builder step: item campaign, land step (re-pin). Receipt: L16, period 7.
  • Any write-activity change lands with the source re-pin in the same pull request, or CI is red whatever the content; every course ships a re-pin script. Builder step: land step (release .37 re-pin). Receipt: L17, period 6.
  • Census live ids before any operator embeds items by id; normalize static check XML before publishing it as an asset; verify rendering with a browser click-through against a live hybrid article. Builder step: p6 article pages. Receipt: L18, period 7.
  • Owner grants are standing authority until the course is live, recorded once in a grant file every window reads; every gate still runs; no clock on the owner's words. Builder step: land step (PR-open and merge hooks). Receipt: L24, period 6.
  • Local gates are never stronger than the factory's, the certification gate excepted; every local gate runs in shadow; progress is stated only in the runbook's phase names. Builder step: every local gate (shadow mode). Receipt: L25, period 3.
  • Budget platform CI: the suite uses most of the 25-minute cap; never fork a process pool inside an xdist worker; use a small-course fixture; test under CI's Python version before pushing. Builder step: land step (CI). Receipt: L29, period 7.
  • A shared Course Builder install is one surface: land on main first, message the other lane with the sha, never install a branch build into the shared root. Builder step: install step. Receipt: L30, period 7.
  • Fan out content lanes (videos, articles, items, FRQs) as parallel shards; scripts and per-item files before agents; every workflow agent carries a fixed-task line. Builder step: content lanes. Receipt: L32, period 7.
  • When the close bar sits in another team's write corridor, file the fallback route in the same issue; ask for the capability, not the token; check a fork is current before declaring code unreachable. Builder step: intake filing. Receipt: L34, period 1.
  • Every status view pairs the current hold with a 'landed so far' line fed from receipts; the event log points at a receiver that exists, and a dispatch nobody receives is an error. Builder step: status pages, event log. Receipt: L42, period 6.
  • A high-severity automated security finding at merge time gets a written disposition on the pull request before the merge. Builder step: land step (merge gate row). Receipt: L44, period 7.
  • Link every out-of-GitHub review round from the pull request so wait and rework are countable. Builder step: land step (PR body). Receipt: L45, period 7.
  • A frozen blueprint is still a document with errors: reconcile it against the authoritative rubric in week one and register a measurable oracle predicate for every requirement at the start. Builder step: step 1 oracle gate. Receipt: L47, period 3.
  • Describe QA work in QA terms; write worker prompts through the codex-prompt skill with the shortest read path; owner asks are two plain sentences. Builder step: review brief; step cards. Receipt: L49, period 6.
  • Defer nothing: no deferred findings in a pull request; a plan date is an intent, not a state. Builder step: land step (admitted-gap scan). Receipt: L50, period 5.
  • Mock forms carry the real exam's option count and everything else carries four; the count is read from the course profile, never converted after generation. Builder step: course profile (p0): mock option count read from the exam; item emit rules. Receipt: L55, period 4.
  • Articles from a source that needs a license are excluded; the course writes its own; a provenance scan runs before any outside body enters a keep or import column. Builder step: article step (p2): provenance scan before any import. Receipt: L56, period 6.
  • A contributor's activity on a course repository is a coordination fact, never ownership or permission; ownership is read from the profile and the remote at intake. Builder step: intake step (p0): ownership read from the profile and the remote; contributor activity as a one-writer coordination row. Receipt: L57, period 3.
  • Cap attempts at the factory's own bounds, then rebuild. one tagging pass per item ended a retry loop; an exhaustion receipt ended a re-post loop that spent about 75 candidates for 0 accepted. Builder step: draft-and-judge loop round cap; needs-human ledger. Receipt: period 2 lessons.
  • Rule at the plan stage on any step whose evidence the factory does not hold; never hold on it. The grader-evidence hold ran 66.4 hours for receipts the factory does not produce. Builder step: plan step; needs-human ledger. Receipt: period 3 lessons.

Factory-canonical operating rules

Open the durable cross-course audit findings.

  • Read the committed factory contract before acting. If the route exists, use it exactly. If it does not, file the gap; do not bridge it locally.
  • Bind inherited factory evidence instead of repeating it. Generation-time QC and hosted grader calibration keep their value when the exact candidate and provenance are linked; an empty downstream folder does not erase them.
  • Measure the review denominator before authoring. Pin blueprint scope, compute current coverage, and generate only the highest-value missing work. Never shrink the denominator after seeing a low score.
  • Keep states separate. Prepared, factory-accepted, merged, deployed, and released are different claims with different evidence.
  • Unknown stays unknown. Missing provenance or an unread receipt blocks credit; prose cannot fill the gap.
  • Approvals are scoped. Investigation, CI success, or a prior owner go does not authorize a new write, paid run, filing, merge, deletion, or release.
  • One writer owns each lane. Other agents may inspect and report, but they do not mutate the same checkout or state.

Safe cleanup sequence

  • Quarantine only exact SHA-verified targets after checking for live processes and locks.
  • Prove the canonical replacement or record a factory contract gap.
  • Retire any status mark that depended on the old machinery.
  • Delete only owner-approved rows whose replacement preconditions passed.
  • Run the residue scan twice and keep remaining blockers explicit.

Current posture: the 16-row purge manifest is approval-gated. No hand-rolled target should be deleted merely because it appears on the list.
