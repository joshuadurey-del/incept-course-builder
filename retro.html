Correction: report the content result with that check set aside (99.84 percent clean), read the reader's code for the cause, add an article text shadow (189 writes) and file the reader gap with its blast radius. Run 1.

What failed, why, and the correction that worked

Thirteen causes cut across the periods; they overlap in time, so their day counts do not add. Each links to its cause section, which ends in the one change for the next build. All thirteen.

  • C1. The publication target moved twice. The student platform target changed 31.9 days in (to TimeBack-direct) and again on 09-18 (everything in AP One, same shape). Two intake waits of 19.4 and 18.0 days closed within a day of the first ruling. Correction: Name the student destination and the full object inventory in the course profile before the first hand-off; when the close bar sits in another team's write corridor, file the fallback route in the same issue. Cause record.
  • C2. The instruments could not read the course. The acceptance runner imported code that lived on one machine, the paid judge would not read items until a structural gate all 933 failed was cleared, and 422 served gate items carried no verdict for 36 days. The hosted reader's rules (one-article context, iframe pages, per-component ordering, a record-size failure that dropped every report email) were learned from paid scores. Correction: Run the acceptance instrument from a pushed ref on a 200-question slice in the first week; read checks.py and timeback_reader.py before any structural write; carry the reader's known needs from the first publish. Cause record.
  • C3. One shared pool, seat, lock and install, with a serial course order. One factory pool, one seat, one writer lock and one Course Builder install served HumGeo first by ruling. Measured waits: 15.0 and 8.2 hours on the pool; seven days with 10 APWH rows against 137 HumGeo rows. Correction: Give each course its own controller lease, lock locator and install root; measure the queue place before every paid step and write the wait into the ETA. Cause record.
  • C4. Owner-word freshness gates and per-step holds. The PR-open and merge hooks wanted an owner quote younger than two hours, and grants were scoped to the transcript they were typed in. Finished work waited 5.2 to 29.5 hours for a morning word. Correction: Standing authority until the course is live, recorded once in a grant file every window reads; gates still run; no clock on the owner's words; an open decision blocks the publish step or carries a typed default. Cause record.
  • C5. Local gates stricter than the factory's. A six-gate contract, an executor no-progress latch and a merge gate that refused on suite rows already red on main added holds the factory did not ask for: 4.9 days of vocabulary, a 66.4-hour hold ruled unnecessary, 10.7 hours on one PR. Correction: State progress only in the publication runbook's phase names; every local gate runs in shadow except the certification gate; a base-red suite gets an adjudication row, not a refusal. Cause record.
  • C6. Live rewrites broke the source envelope. The producer hashes every item, so each live item wave broke the source envelope and needed a source re-pin plus a full republish (about 2,300 writes and 65 minutes). Four re-pins landed between 01:08Z and 10:32Z on 2026-09-18 (9.4 hours by subtraction, as the period 7 record states); 3,480 rewrites were unfolded at the cut. Correction: Make the re-pin a step of the item-campaign operator (plan, seal, execute, replay, re-pin) and keep the publisher's checkpoint in the repository so a re-pin republishes only what changed. Cause record.
  • C7. The measurement layer was wrong or stale. A report header frozen for 10.9 days, a stale branch that turned MISSING into PASS, stale-clone counts, a false '24 tests broken' claim, an event feed that dropped rows for 11 days, and a status view that hid three weeks of landed work. Correction: Re-derive every quoted number from the live remote in the same turn; assert that a regenerated report changed; pair every hold with a 'landed so far' line; point the event log at a receiver that exists. Cause record.
  • C8. Review ceremony, capped review lanes and a tight CI budget. Six or seven review rounds on one PR, two capped rounds with no verdict, a draft PR that sat 75.4 hours outside merge policy, CI timeouts on a forked pool, and out-of-GitHub rounds nobody could count. Correction: Every review finding returns with a deterministic, tested fix; a capped lane writes its report file first; PRs post ready-for-review; a small-course fixture keeps the suite under the CI cap; out-of-GitHub rounds are linked from the PR. Cause record.
  • C9. The publication contract arrived after the content. The 910-line runbook was handed over on 08-28 and never committed; on 09-08 the native pipeline stopped at Phase 2. The Phase 6 operators merged 17.0 days after Phase 2 pricing, and one plan needed five versions in a day because version 1 assumed modules that did not exist. Correction: Commit the publication runbook and a per-phase module inventory (exists or missing) to the course repository on intake day; plan from that inventory, never from an assumed pipeline. Cause record.

A publish run died with its shell; a Mac restart killed the after-wave chain (13.75 hours from restart to re-bind); another lane installed a release over this lane's build; a full disk stopped every tool.
